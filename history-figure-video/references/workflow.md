## 3 文案改写+避多音字+去AI味+质检(同步,30-60s)

### 3a 文案改写

将史料改写为短视频旁白脚本。

**改写原则**:
1. 口语化:文言→大白话,7岁小孩也能听懂
2. 悬念结构:开篇钩子(正史vs野史矛盾),中间递进,结尾留悬念/金句
3. 叙事感:用"话说""你猜怎么着""谁能想到"等口吻
4. 短句为主:每句不超过20字
5. **易中天式说史风格**(核心文风):
   - **移时**:用现代词汇翻译古代事物,制造时空错位的幽默感。如:宰相=CEO,掖庭=宫里的底层打工人,才人=给个编制
   - **口语化**:像聊天不像讲课。"什么意思呢？""换句话说""也就是说""结果呢？"——设问+自答,像说书人的扣子
   - **反讽**:正话反说,笑里藏刀。"气量很大,只是被气死了"
   - **生活化比喻**:把权谋变成日常。政治斗争=人事变更+利益再分配,罪臣之女=创业失败者的孩子
   - **一针见血**:不铺垫,直接给结论。"琢磨计谋没用,你还是琢磨人性吧"
   - **节奏**:短句+设问+停顿+答案,一句一个意思,不绕
   - 核心原则:历史其里,文学其表——用现代人的嘴说古代的事,用生活里的常识解权力里的迷
6. **正史为主,野史为辅,标注出处**:
   - 核心事件以正史为准,不编造
   - 野史细节作为"另一种说法"引入,增加悬念和争议感
   - 旁白中明确标注出处,如:"《旧唐书》说她……但《朝野佥载》却记载……"
   - 墓志铭出土内容与正史矛盾时,重点呈现——天然翻案素材
   - 出处标注格式:
     - 正史:直接引用,如"《旧唐书》记载……"
     - 野史/笔记:引用+提示,如"《北户录》记载……但此书成于中晚唐,可靠性存疑"
     - 墓志:重点标注,如"2013年出土的墓志铭却给出了完全不同的说法……"
     - 学术观点:如"学者仇鹿鸣认为……"
7. **结合历史背景**:必须交代当时的政治格局、社会环境、制度背景
8. **点明历史局限性**:对人物缺点结合时代背景说明,不洗白也不苛责
9. **避多音字**:按 `references/polyphone-replace.md` 替换策略逐字检查
10. 每集结尾:非末集留悬念+"读史明事理,平章说,下集见",末集总结+互动+"读史明事理,平章说"

**改写模板**,每集拆5-8个小节:

```json
{
  "ep": 1,
  "title": "刀下留人",
  "figure_name": "上官婉儿",
  "dynasty": "唐",
  "opening_hook": "平章说,她爷爷被武则天杀了,她却成了武则天最信任的人",
  "sections": [
    {
      "title": "章节标题(4-6字)",
      "narration": "旁白文本(80-200字/节)",
      "source": "《旧唐书》/《北户录》/墓志铭等",
      "bg_prompt": "AI生图提示词",
      "type": "cover|hook|story|reversal|ending"
    }
  ],
  "ending_hook": "下集悬念文本",
  "total_chars": 800
}
```

**⚠️ script.json必填字段检查清单(每集都必须包含,缺一不可)**:
- `ep` — 集数
- `title` — 集标题
- `figure_name` — 人物姓名(封面页使用,每集必填!)
- `dynasty` — 朝代(封面页使用,每集必填!)
- `opening_hook` — 开篇钩子
- `sections` — 小节数组
- `ending_hook` — 结尾悬念
- `total_chars` — 总字数

**⚠️ sections[0]的type必须为"cover"** — 每集第一个section必须是封面页(type=cover),不能是hook或其他类型。封面页只显示"历史人物/姓名/朝代"三行,不显示旁白文案。hook内容放在section[1]或opening_hook字段中。
```

- 开篇用固定钩子(opening_hook)
- 每集narration总字数600-1200字
- bg_prompt格式:"中国风历史画,[场景描述],深色调,8K高清,竖构图"

### 3b 避多音字检查

**必须**用pypinyin逐字检查旁白文本,标记所有多音字。检查脚本见 `references/polyphone-replace.md`。

**所有多音字必须替换为无歧义表达**。

### 3c 史实排错(必做)

文案写完后、质检前,**必须**逐项核查以下6类史实错误。发现任何一项即打回修改。

| 检查项 | 方法 | 常见错误 |
|--------|------|----------|
| **年代** | 关键事件年份×人物年龄交叉验证 | 出生年≠事件年-年龄、在位时间算错 |
| **人物关系** | 父子/祖孙/君臣/姻亲逐条核对 | 爷爷写成父亲、同辈写成上下级 |
| **官职/封号** | 查正史本纪/列传,注意时间线 | 封号在事件发生时还未授予 |
| **引文准确性** | 墓志铭/正史原文逐字比对 | 断章取义、张冠李戴、翻译偏差 |
| **时间跨度** | 起止年份相减,与文案表述对比 | "三十年"实际只有十四年 |
| **出处标注** | 每条标注是否与实际来源一致 | 野史标注为正史、墓志内容标注为旧唐书 |

**执行流程**:
1. 提取文案中所有**可验证事实**(人名、年份、年龄、官职、引文、出处)
2. 逐条用web_search交叉验证(至少2个独立来源)
3. 墓志铭原文必须与出土全文逐字比对
4. 发现错误→立即修正→重新验证修正后的事实
5. 输出《史实排错报告》,列出:✅已验证 / ❌已修正 / ⚠️存疑(附理由)
6. 报告存入 `script_fact_check.md`,随script.json一起保存

**⚠️ 存疑处理**:无法确认的事实,文案中必须加限定词("据说""传说归传说""有说法认为"),不得以肯定语气陈述。

### 3d 去AI味

同folk-story-video的6步流程(黑名单→否定转肯定→剥离心理锚点→对话排毒→形容词压缩→逐句自检)。详见 `references/deai-checklist.md`。

### 3e 文案质检

七角色评审,最低分 ≥ 90 才通过。

| 角色 | 检查重点 |
|------|----------|
| 阅读者 | 开篇吸引力、节奏、画面感 |
| 编审 | 错别字、标点、措辞 |
| 故事家 | 因果、剧情推进 |
| 史实复核员 | 审查3c排错报告有无遗漏、移时比喻是否误导历史认知 |
| 文学顾问 | 层次、细节、活性 |
| 毒舌读者 | AI味残留、水字数 |
| TTS审查员 | 多音字残留、绕口表达、TTS不友好标点 |

最低分 < 90 → 重写,最多3轮。

完成后:保存 `script.json`(必须包含`figure_name`和`dynasty`字段),**验证script.json必填字段完整后再继续**,更新 `progress.json`(current_step=3),汇报用户。

## 4 AI生图(后台,2-5min)

**⚠️ 绝对禁止自行编写生图脚本。生图只能通过以下命令执行，不得修改、不得替换、不得绕过：**

```bash
python3 ~/.openclaw/skills/history-figure-video/scripts/generate_images.py <episode_dir>
```

**⚠️ 如果你在步骤4中写了任何新的.py脚本或调用了任何非百度API，你就是在犯错。**

**⚠️ 文生图必须串行调用，禁止并发。每次只调一张图，等上一张完成后再调下一张。多集制作时也必须逐集串行，禁止同时为多集生图。**

**⚠️ TTS_API_KEY仅用于TTS(步骤6)，严禁用于文生图。DashScope的wanx-v1、image-synthesis、multimodal-generation等文生图API一律禁止调用。**

脚本读取script.json的bg_prompt，调用百度AI Studio API(`BAIDU_API_BASE/images/generations`)生成图片，失败时PIL渐变兜底。输出到 `images/ai_{NN}.png`。已存在的有效图片(>50KB)会自动跳过。脚本内部已强制串行（逐张生成，每张间隔1秒）。

### 生图风格

- **不用"水墨画"**,改用"中国风历史画"或"工笔重彩"
- 场景具体:宫殿/战场/书房/市井/荒野
- 人物用剪影或侧脸,避免AI生人脸异常
- 色调偏暖(历史感)

示例prompt:
- 封面:`中国风历史画,唐代宫殿剪影,金色夕阳,大气磅礴,8K高清,竖构图,无文字无汉字`
- 故事:`中国风历史画,古时女子在书房写字,烛光映照,暖色调,8K高清,竖构图,人物剪影,无文字无汉字`
- 结尾:`中国风历史画,远山落日,孤影独立,意境深远,8K高清,竖构图,无文字无汉字`

**⚠️ 生图prompt禁用规则**:
- **禁止使用"古代""年代""时代"等含"代"字的词**——AI图像模型会把"代"字渲染到画面上！用"古时""旧时""昔日"替代
- **所有prompt末尾必须加"无文字无汉字"**——防止AI在画面上生成乱字
- **禁止在prompt中出现任何中文单字**（如"商""周""唐"等朝代名单独出现时也可能被渲染）——用完整描述替代，如"商朝时期"写成"青铜器时期"或直接描述场景

完成后:更新 `progress.json`(current_step=4),汇报用户。

**⚠️ AI生图输出文件名约定**:每张图保存为 `images/ai_{NN}.png`(NN为section索引,从00开始)。步骤5的screenshot.py会读取这些图片作为背景。

### publish.txt 格式参考

compose_video.py 已内置自动生成,以下格式供手动修改时参考:

文件路径: `{episode_dir}/publish.txt`

三行格式:
```
标题（第一行）
简介（第二行）
话题（第三行）
```

**标题**: `姓名(序号)：标题内容`
- 序号用中文数字:一、二、三、四
- 标题内容取自script.json的title字段
- 示例: `妲己(一)：有苏之女`

**简介**: 1-2句话提炼本集核心冲突/反转/看点
- 风格:悬念+反常识+故事感
- 不用"今天我们来讲"等套话

**话题**: 3-5个话题标签
- 必带: `#平章说` `#{人物名}` `#{朝代}`
- 选带(按内容选1-2个): `#历史真相` `#封神演义` `#考古` `#甲骨文` `#女将军` `#姓氏起源` `#正史vs野史` `#竹书纪年` `#牧野之战` `#殷墟` `#军事史`
- 知识赛道加: `#人文社科` `#知识创作`

**示例**:
```
妲己(一)：有苏之女
有苏氏战败献女求和，"妲己"不过是族姓拼出来的称呼。正史对她只写了一句，后世却加了无数罪状。
#平章说 #妲己 #商朝 #历史真相
```
